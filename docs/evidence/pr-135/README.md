# PR #135 visual evidence: homepage desktop after removing one client project

The PR description already shows Before/After for `/projects?category=Client`.
This folder adds the homepage, because the committed static homepage
(`public/static-home.<hash>.html`) is regenerated by this PR and its stats

Capture: Playwright Chromium (headless shell 151), viewport 1440x1000,
`deviceScaleFactor: 1`, light color scheme, `reducedMotion: reduce`,
`waitUntil: networkidle` plus `document.fonts.ready`, viewport-only screenshot.

Why After is a local build: the homepage is a committed static document
(`/` rewrites to `public/static-home.<hash>.html`), so the bytes a local
`next start` serves are the bytes Vercel serves. The After build came from a
fresh `git clone` followed by `npm ci && npm run build`, which is the same
sequence the PR head `6fa0cbc` failed on (its manifest pointed at
`static-home.43018055cd8c9c2d.css` / `static-home.0d66bcac151b6974.html`,
which were never committed). Commit `11c3393` re-ran `npm run sync:static-home`
from the committed tree; the regenerated CSS differs from `main` only by
dropping the one gradient-start color utility that the removed project card
alone used, and the regenerated HTML differs only by the CSS filename and
the two stat counts.

Note for future evidence writers: Tailwind scans every non-ignored text file
in the repo (this README included) for class candidates, so even a bare color
name in prose can change the generated homepage CSS hash. That is how the
`6fa0cbc` manifest came to reference hashes no clean checkout can reproduce:
it was synced with uncommitted text in the working tree. Always run
`npm run sync:static-home` from a clean tree and commit every file it writes.
